# Технологический стек (MVP)

Документ описывает **текущий технологический стек и организацию проекта** на этапе MVP. Используется как опорная спецификация для разработки и масштабирования.

---

## Общий подход

Проект реализуется в формате **monorepo** — один репозиторий, в котором живут бот, backend и frontend.

Цели такого подхода:

- единый TypeScript-стек end-to-end
- единые подходы к конфигурации и стилю кода
- возможность шарить типы и доменные модели
- удобная работа с AI-инструментами (Copilot и др.)
- упрощённое масштабирование проекта

---

## Telegram Bot

**Расположение:** `apps/bot`

**Стек:**

- Node.js
- TypeScript
- **grammY**

**Назначение:**

- обработка команд Telegram-бота
- точка входа пользователя в продукт
- отправка кнопки открытия Mini App (`web_app`)

---

## Backend API

**Расположение:** `apps/api`

**Стек:**

- Node.js
- TypeScript
- **Fastify**

**Назначение:**

- валидация `initData`, приходящего из Telegram Mini App
- авторизация пользователя
- реализация бизнес-логики (на следующих этапах)

**Принципы:**

- простая структура на MVP
- чёткие границы ответственности
- готовность к расширению без переписывания ядра

---

## Frontend — Telegram Mini App

**Расположение:** `apps/web`

**Стек:**

- React
- Vite
- TypeScript

**Назначение:**

- UI Telegram Mini App
- взаимодействие с Backend API
- отображение состояния игры

---

## Telegram Mini App SDK

**Используемая библиотека:**

- `@twa-dev/sdk` (npm)

**Используется для:**

- доступа к `Telegram.WebApp`
- получения `initData`
- корректной инициализации Mini App внутри Telegram

---

## Структура репозитория (MVP)

```
/apps
  /bot        # Telegram Bot (grammY, TypeScript)
  /api        # Backend API (Fastify, TypeScript)
  /web        # Telegram Mini App (React, Vite, TypeScript)
/packages
  /shared     # общие типы и утилиты (добавляется позже)
```

---

## База данных

На этапе MVP: **позже разберёмся**.

Сначала реализуется вертикальный срез:
**бот → Mini App → API → авторизация**.

Выбор СУБД и ORM откладывается до момента, когда станет понятно:

- какие сущности реально используются
- какие операции критичны по производительности
- какие данные должны быть консистентны

---

## Примечание

Документ живой и будет дополняться по мере развития продукта. На этапе MVP приоритет — скорость, ясность и рабочая вертикаль, а не избыточная инфраструктура.
